## Executive status

The v0.1.1 Navigation Core implementation is present on `main`. The Stage 1–3.7 work below provides increasingly broad numerical and synthetic-scenario evidence. It does **not** establish physical navigation accuracy, calibrated sensor performance, real GNSS/RINEX integration, or production readiness.

No ML training was run. No GitHub Actions workflow was introduced. The Stage 3.7 instrumented reproduction did not modify the repository during execution.

## What has been verified

### Mathematical implementation and deterministic checks

- Hamilton quaternion convention, scalar-first representation, and body-to-ENU rotation were inspected.
- The error-state convention is right-multiplicative; the attitude error calculation and injection convention were found internally consistent in the inspected code.
- The 15-state error vector uses position, velocity, attitude, accelerometer bias, and gyroscope bias blocks, each three-dimensional.
- GNSS position update uses a position-selection observation matrix.
- Measurement update uses a Joseph-form covariance update, followed by error injection and covariance reset.
- The reset Jacobian finite-difference residual decreased quadratically as the test perturbation was halved:

| Perturbation scale | Maximum absolute Jacobian difference |
|---:|---:|
| 1.0000 | 3.462630e-03 |
| 0.5000 | 8.664143e-04 |
| 0.2500 | 2.166509e-04 |
| 0.1250 | 5.416569e-05 |
| 0.0625 | 1.354160e-05 |

This supports the expected local first-order reset Jacobian behavior; it is not a proof of global filter correctness.

### Stage 1 — numerical sanity

The following checks passed in the Colab run:

1. Continuous error-state matrix finite-difference check.
2. Van Loan discretization convergence check.
3. Long-run covariance finite/symmetric/PSD check.
4. Gaussian NIS distribution sanity check.
5. Gaussian NEES distribution sanity check.
6. Noise sensitivity check.

The NIS/NEES distribution checks sampled known Gaussian residual/error distributions directly. They were not yet empirical filter-consistency tests.

### Stage 2 — Monte Carlo baseline

Thirty synthetic runs were performed for continuous GNSS and temporary GNSS outage.

- Continuous GNSS: NIS mean 2.925 (3 DoF theoretical mean 3); position NEES mean 3.197.
- GNSS outage: NIS mean 3.075; position NEES mean 2.935.
- Position covariance trace increased from 0.251 at outage start to 16.583 at outage end, then decreased to 0.675 after the first GNSS correction.

These are synthetic diagnostics with placeholder noise parameters. The Stage 2 implementation did not calculate position error at every IMU epoch during the outage.

### Stage 3 — dynamic synthetic stress

Twenty runs per scenario were executed for acceleration, turning, 3D motion, and GNSS outage.

For acceleration, turning, and 3D motion, position NEES means were approximately 2.89–2.94 and NIS means approximately 3.01–3.04. Full 15-state NEES and coverage showed weaker consistency in some scenarios.

The GNSS-outage scenario showed materially larger position errors during outage and elevated full-state NEES. The initial Stage 3 report was marked `COMPLETED_REQUIRES_REVIEW`.

### Stage 3.1–3.6 — paired and statistical diagnostics

- INS-only and INS/GNSS filters were compared using paired runs, shared truth, and shared IMU realizations.
- The paired experiment showed lower position RMSE for INS/GNSS in all 20 runs in every reported phase.
- Filter state/covariance ownership was audited; the tested instances did not share mutable state or covariance.
- Error and covariance were collected at the same IMU epoch; GNSS corrections were applied before collection at GNSS update epochs.
- The attitude error convention matched the right-multiplicative injection convention.
- The reported NEES coverage metric is an **upper-threshold acceptance fraction** (`NEES <= chi-square upper 95% threshold`), not a two-sided 95% interval coverage statistic.
- Full-state NEES is not the sum of marginal block NEES values; cross-covariances matter.

### Stage 3.7 — covariance snapshots

A focused reproduction of scenario `D_gnss_outage` ran 20 paired trials and captured both filters at six instants:

`7.99, 8.00, 12.00, 17.99, 18.00, 18.20 seconds`.

**Capture integrity:** 240/240 snapshots; 120 per filter; zero invalid covariance flags.

Mean INS/GNSS covariance traces:

| Time | Position trace | Full 15-state trace | Interpretation |
|---:|---:|---:|---|
| 7.99 s | 0.247584 | 0.459876 | Before outage |
| 8.00 s | 0.251169 | 0.465109 | Outage begins |
| 12.00 s | 17.216893 | 19.867300 | During outage |
| 17.99 s | 512.092640 | 536.650000 | End of outage |
| 18.00 s | 0.741668 | 1.180250 | GNSS update has been applied |
| 18.20 s | 0.390578 | 0.835102 | Subsequent update |

At 18.00 s, the position covariance trace fell by approximately 99.86% relative to 17.99 s. The reduction in other state blocks is consistent with indirect correction through cross-covariance, but the exact update contribution still requires auditing the innovation and Kalman gain.

The INS-only covariance also grew substantially, as expected without external position corrections. This is not evidence of INS/GNSS failure.

## Open engineering questions

1. Audit the GNSS innovation, innovation covariance, Kalman gain, and state correction at the 18.00 s update.
2. Verify that the indirect corrections to velocity, attitude, and bias states are consistent with the pre-update cross-covariances.
3. Compare independently computed Joseph posterior covariance with the filter's actual posterior covariance.
4. Investigate elevated full-state NEES, especially during outage and recovery, using the exact error/covariance convention and upper-tail coverage definition.
5. Review attitude and bias consistency under dynamic excitation.
6. Calibrate IMU noise and bias random walks from real sensor data before drawing physical conclusions.
